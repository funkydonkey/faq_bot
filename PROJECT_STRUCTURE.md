## What Goes Where?

### 📝 Adding New Features

**New agent or module:**
```bash
# Create in src/
touch src/my_new_agent.py
```

**New utility script:**
```bash
# Create in scripts/
touch scripts/my_utility.sh
chmod +x scripts/my_utility.sh
```

**New test:**
```bash
# Create in tests/
touch tests/test_my_feature.py
```

### 📚 Documentation

**User-facing docs:** Root directory (markdown files)
**Developer notes:** Add to CLAUDE.md
**Architecture diagrams:** Add to ARCHITECTURE.md

### 🗑️  What NOT to Commit

The `.gitignore` file excludes:

- ✅ `__pycache__/` - Python cache
- ✅ `.env` - API keys (NEVER commit!)
- ✅ `venv/` - Virtual environment
- ✅ `docs/` - User documents (private)
- ✅ `kb/` - Generated knowledge base
- ✅ `logs/` - Application logs
- ✅ `*.db` - Databases
- ✅ `.DS_Store` - macOS files
- ✅ `MiniRAG/` - External dependency

### ✅ What TO Commit

- ✅ Source code (`src/`)
- ✅ Scripts (`scripts/`)
- ✅ Tests (`tests/`)
- ✅ Documentation (root `.md` files)
- ✅ Configuration (`requirements.txt`, `.gitignore`)
- ✅ Entry points (`run_app.py`, `run_config.py`)

## Structure Rules

### Rule 1: Keep Root Clean
Only entry points and documentation in root directory.

### Rule 2: Code Goes in src/
All Python modules belong in `src/` package.

### Rule 3: Scripts are Executable
Utility scripts in `scripts/` should be executable (`chmod +x`).

### Rule 4: Tests are Separate
All test files in `tests/` directory.

### Rule 5: No Compiled Files
Never commit `__pycache__/`, `.pyc`, or `.db` files.

## Maintenance

### Regular Cleanup

```bash
# Remove Python cache
find . -type d -name "__pycache__" -exec rm -rf {} +

# Remove temporary files
rm -rf data/ docs_md/

# Check for old files
ls -lt | head -20
```

### Structure Validation

```bash
# Run structure test
python tests/test_structure.py

# Should show: 23/23 tests passed
```

### Git Status Check

```bash
git status

# Should NOT show:
# - __pycache__/
# - .env
# - *.db files
# - docs/ or kb/
```
